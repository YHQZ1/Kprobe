# kprobe — Project Instructions

## What is kprobe

kprobe is a deep kernel observability tool for distributed financial systems. It sits at the Linux kernel level using eBPF and captures everything — network packet timing, CPU scheduling decisions, memory pressure events, database write latency — without touching a single line of application code.

When an incident occurs, it constructs a full causal graph of exactly what caused what, down to the kernel-level event that triggered the failure. It then lets you replay the entire incident deterministically, on a dev machine, hours after it happened.

It is not a monitoring tool. It is not a tracing tool. It is a flight recorder and a debugger for distributed financial systems.

**One-liner for technical context:**
> An eBPF-based causal profiler with deterministic replay, built specifically for distributed financial systems — zero instrumentation overhead, kernel-level visibility, financial domain primitives baked in.

---

## Key Technical Decisions (locked in — do not revisit)

- **Pure Rust/Aya for the eBPF probe** — both kernel-side and userspace. No C anywhere. Aya compiles Rust directly to eBPF bytecode. This is a deliberate decision for memory safety and developer ergonomics.
- **Separate Go modules per service** — `engine`, `api`, `replay` each have their own `go.mod`. They share code only through the `shared/` module. This keeps services independently deployable.
- **`go.work` workspace at the root** — local dev convenience only. Does not affect production builds or CI.
- **Split dev model** — infrastructure (Kafka, ClickHouse, Neo4j) runs in Docker Compose. Go services and the frontend run natively. No Docker rebuilds during development.
- **Kafka in KRaft mode** — no Zookeeper dependency.
- **ClickHouse for raw event storage** — columnar, handles billions of timestamped rows, sub-second queries.
- **Neo4j for causal graph storage** — graph traversal from any financial event back to root kernel cause.
- **Vector for correlation** — joins raw eBPF events with OpenTelemetry traces on PID + timestamp before the causal engine sees them.

## Kernel Hooks (eBPF tracepoints)

| Hook            | What it captures                        |
| --------------- | --------------------------------------- |
| `tcp_sendmsg`   | TCP send — network packet timing        |
| `tcp_recvmsg`   | TCP receive — network packet timing     |
| `sys_read`      | Syscall read — database read latency    |
| `sys_write`     | Syscall write — database write latency  |
| `sched_switch`  | CPU scheduling decisions                |
| `mm_page_fault` | Memory pressure events                  |

---

## Financial Domain Primitives (shared/domain)

- `Settlement` — trade settlement with state machine (Pending → Clearing → Settled → Failed)
- `Order` — financial order (symbol, side, qty, price)
- `LedgerEntry` — append-only financial record
- `SettlementState` — enum for settlement lifecycle
- `OrderSide` — Buy / Sell

---

## Event Types (shared/types)

- `KernelEvent` — raw eBPF event (TimestampNs, PID, TID, CPU, EventType)
- `EventType` — enum: TCPSend, TCPRecv, SyscallRead, SyscallWrite, SchedSwitch, PageFault
